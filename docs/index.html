Umidl

本地视频下载 · 80 种格式转换 · AI 字幕——全部由本机进程完成

03四大模块

下载、转换、字幕、插件——一条链在本机闭环，模块之间的数据都走本地文件与进程。

下载 Download

  • 两条下载链路按链接类型自动路由
  • 分P、合集、HLS/DASH 自动合并
  • 暂停 / 断点续传 / 取消 / 删除；列表式队列（非卡片）
  • 每任务连接数可调，范围 1 – 16，越界自动限幅
  • 批量导入：多行链接或文本文件，逐条给出已加入 / 跳过及原因
  • 全局限速（令牌桶）；系统代理自动识别，内网与回环强制直连

转换 Convert

  • 80 种目标格式：视频 22 · 音频 20 · 图片 20 · 文档 18，按分组芯片 + 搜索浏览
  • 可选格式由本机引擎能力探测决定，探测不到的格式不会出现在列表里
  • docx / xlsx / pptx / odt / ods / odp 纯 Rust 原生解析，无需外部运行时
  • 富文本互转与 PDF 文本抽取各由对应引擎承担
  • 硬件编码 NVENC / QSV / AMF，各自匹配对应码控参数
  • 自动探测输入编码：已是 H.264/AAC 时无损封装而非重编码
  • 实时进度与取消；CRF / 分辨率 / 码率 / 语速等参数按目标类型显隐

字幕 Subtitle

  • 语音识别在本机进程内完成，音频文件不离开这台机器
  • 识别语言可多选（自动检测 + 8 种语言），可叠加「翻译成英文」轨道
  • 6 档模型按需下载：75 MB · 142 MB · 466 MB · 1.5 GB · 1.6 GB · 3.1 GB
  • 导出 SRT / ASS / VTT / TXT / JSON 五种格式
  • 流程：FFmpeg 提取音频 → Whisper 识别 → 生成时间轴 → 导出字幕文件

插件 Plugins

  • 沙箱硬上限：16 MB 内存 · 512 KB 栈 · 200 ms 单次执行，超限即中断
  • 白名单 API：umi.log / resolve / registerResolver / on / retry / storage，不提供 require / process / fetch
  • 插件注册的解析器参与「这条链接交给哪条链路」的判定
  • 事件钩子：download:done / download:error / app:start
  • umi.retry(taskId) 命令式重试，自带次数上限
  • 插件市场按内容寻址校验 sha256；事件日志每次运行最多保留 200 条

04工程与安全约定

下面这些是代码里实际生效的约束，不是宣传语：能在源码中逐条核对，也能在界面里直接观察到。

🔒

本地处理边界

程序不包含上传、账号与遥测链路：下载、转码、语音识别都在本机进程内完成，除了抓取远端文件本身，其余功能不需要网络。卸载或删除数据目录即可清除全部状态。

📦

依赖工具托管，不动 PATH

各引擎按需下载到托管目录（截图中为 D:\Umidl\data\bin），不改系统 PATH、不写全局环境变量；查找顺序为：用户指定路径 → 托管目录 → 主程序同级 → 系统 PATH。设置页可校验所选工具的完整性，或补装缺失项。

🚦

批量导入与限流

粘贴或导入文本上限 512 × 1024 字符，超出直接拒绝；重复链接会被跳过。每任务连接数 1 – 16 可调、越界自动限幅，另有全局令牌桶限速，避免批量任务占满带宽。

🎨

四语言与可换肤

界面支持简体中文 / English / 日本語 / Français；中文原文即翻译 key，缺失翻译自动回退中文。主题两态（浅色 / 深色）、六种预设强调色，自定义强调色与自定义渐变收进同一张卡的折叠区、粒子背景可关闭。窗口图标可替换，PNG / JPG / WEBP / SVG / ICO，上限 4 MB。

✅

提交前的四条门禁

npx vue-tsc --noEmit              # 类型检查
npx vitest run                    # 前端单元测试
cd src-tauri && cargo test --lib  # Rust 单元测试
python scripts/check_i18n_catalog.py  # 四语言 key 集合一致

四条门禁中的前三条同样会在 release 工作流里执行；本页引用的沙箱上限、连接数限幅、批量文本上限等数值，在仓库里都有对应的单元测试。

已知限制与适用边界

  • macOS 产物未做代码签名与公证：首次打开需要右键 → 打开（或在「系统设置 → 隐私与安全性」放行）。
  • macOS 与 Linux 产物由 CI 构建，尚未在对应真机回归；Windows 产物已在本机完成安装与启动实测。
  • macOS / Linux 上分段下载引擎没有官方静态包，需要经 Homebrew / apt 安装，应用会在缺失时给出对应命令。
  • Android 需要移动端适配，暂无产物；CI 中的 Android 作业为实验性（失败不阻塞发布）。
  • 外部引擎与 Whisper 模型在首次使用时按需下载，因此需要网络；完全离线的机器要自行准备这些文件。
  • 程序不含遥测与崩溃上报：反馈问题需要手动提供版本号、操作系统与日志。

06参与贡献

不只有写代码：翻译、文档、插件示例，尤其是 macOS / Linux 真机测试，都是当前缺口。

当前缺口

① macOS / Linux 真机回归：这两个平台的产物只跑过 CI 编译，需要有人实机走一遍下载、转换、字幕三条链路；② 四语言包的翻译补全与校对；③ 文档与插件示例；④ 桌面端之外的适配探索。

i18n 约定

中文原文即 key：t('保存')。新增文案先在四个语言包（zh / en / ja / fr）补齐，再在代码里引用；语言包保持 2 空格缩进与 LF 行尾（与主分支一致），不要整文件重排。

硬约定（破坏即拒改）

不改标识符 com.umi.downloader；不改数据目录 %APPDATA%/umi-downloader；不污染系统 PATH；不引入上传或遥测。

07许可证与第三方组件

为什么是 AGPL-3.0

Umidl 本身是纯本地桌面程序，自己电脑上使用不产生任何额外义务。它带一个可编程插件沙箱——AGPL 的「网络交互」条款可以确保：把它包装成网络服务对外提供的一方，必须公开其修改后的源码。

运行时获取，不随包分发

下表所列是独立程序：Umidl 只负责调度与参数拼装，首次需要时把它们下载到托管目录（或复用你已装好的副本）。它们各自遵循自己的许可证，与 AGPL-3.0 无关，源码也不在本仓库内。
