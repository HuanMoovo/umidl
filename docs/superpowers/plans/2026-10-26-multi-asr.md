# Multi-engine Subtitle Recognition Implementation Plan

**Goal:** User selected both local Chinese ASR and cloud transcription while retaining the integrated simple UI. Add local SenseVoice and Paraformer (FunASR-family models executed by sherpa-onnx), plus a timestamp-capable OpenAI/Whisper-compatible cloud API.

**Constraints:** Keep Whisper as default and all existing behavior. No paid API calls or private uploads during development. Cloud API key is session-only and never persisted in settings, task request JSON, logs or diagnostic errors. Local runtime/model downloads occur only through the explicit install action. No platform video-compression feature.

## Interfaces

New Rust modules `local_asr.rs` and `cloud_asr.rs` share existing `subtitle::Cue` and `Ctx`.

- Local: `engine_status(ctx: &Ctx, engine: &str) -> serde_json::Value` returns `{engine,runtime_ready,model_ready,ready,message,model_dir}`. `install_engine(ctx: &Ctx, engine: &str) -> anyhow::Result<()>`. `transcribe(ctx: &Ctx, wav: &Path, engine: &str, language: &str, register_pid: &dyn Fn(u32), is_cancelled: &dyn Fn() -> bool) -> anyhow::Result<Vec<Cue>>`.
- Cloud: `CloudAsrConfig {base_url:String, model:String, api_key:String}`; Debug must redact key. `transcribe(ctx: &Ctx, wav: &Path, config: &CloudAsrConfig, language: &str, translate_to: Option<&str>, is_cancelled: &dyn Fn() -> bool) -> anyhow::Result<Vec<Cue>>`. Use verbose_json segment timestamps. Support long 16kHz mono PCM WAV by bounded chunks; include offsets. HTTPS remote endpoints, HTTP loopback for local compatible services/tests. Disable redirects that could leak credentials.
- New commands (integrator): `asr_engine_status(engine:String)`; `install_asr_engine(engine:String)`; `start_asr(req:AsrRequest)`. `AsrRequest {engine:String, subtitle:SubtitleRequest, cloud:Option<CloudAsrConfig>}`. Existing `SubtitleRequest` remains unchanged.
- New jobs use existing subtitle queue/events, extraction, cancellation, export renderers, and uniquely reserved output paths. They persist only redacted metadata, never cloud credentials. Translation is offered only for supported providers; local Chinese models are transcription-only.
- Frontend new `services/asr.ts` invokes commands. Default Whisper retains current service, tools/models/download/import controls. Chinese choice has SenseVoice/Paraformer and per-engine status/install. Cloud choice has Base URL, model, session-only password key and upload disclosure. Other engine configuration remains hidden. No changes to locale files by workers; report keys to integrator.

## Work

1. Local worker: implement managed private Python/sherpa runtime, official model download/setup, timestamped recognition and cancellation; embed worker source. Validate packages/models only on explicit install, never execute arbitrary model code. Safe bounded archive extraction. Tests and optional real CPU smoke.
2. Cloud worker: implement endpoint validation, multipart/chunking, timestamp parsing, failures/cancellation and key redaction. Use a local HTTP test server; no live paid API calls. Root enables existing reqwest multipart feature if required.
3. UI worker: integrate the three engine choices without clutter; snapshot in-flight selections; maintain all existing Whisper tests. Meaningful regressions plus new engine payload tests. Do not persist key or engine-specific cloud options to settings.
4. Integrator: add modules and command/job orchestration, render outputs, merge translations, test full app, review new boundaries, rebuild final installer and update original project with baseline-conflict/hash protection. Existing upgrade backup remains the pre-upgrade source.

## Verification focus

- Old Whisper requests remain valid and unchanged.
- Key absent from any database JSON and error logs; endpoint redirects disabled.
- Local recognition never uploads audio; model and runtime downloads are explicit.
- Time axes use actual recognizer or service timestamps; reject missing timestamps for subtitle output rather than claiming precision.
- Cloud chunk offsets, blank/silent audio, cancellation and partial failures do not become false success.
- UI choice/install/model races preserve the user's most recent selection.
