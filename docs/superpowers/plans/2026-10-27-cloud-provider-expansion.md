# 主流语音 API 扩展实施计划

**Goal:** 在现有字幕流程内支持九家已确认服务商和自定义 Whisper 兼容接口，准确生成带时间戳的字幕。
**Architecture:** 沿用 `CloudAsrConfig` 和字幕任务；按 `provider` 分派至官方适配器，统一处理音频分块、时间偏移、导出与取消。界面仅显示当前服务的必要字段。配置提供向后兼容的 `compatible` 默认值。
**Spec:** `outputs/主流语音API扩展方案.md`（用户 2026-10-27 确认全部范围）。
**Stack:** Rust/Tauri，Vue 3，reqwest，现有字幕格式与独立测试环境。

## 执行分工

1. 国内同步及异步：`src-tauri/src/cloud_vendor_cn.rs`，实现腾讯、百度、讯飞，模拟服务覆盖签名、上传、轮询及错误。
2. 国际同步：`src-tauri/src/cloud_vendor_sync.rs`，实现 Fish、Deepgram、Azure，模拟服务覆盖格式、时间戳和错误。
3. 前端：`src/views/Subtitle.vue`、`src/services/asr.ts`、四语言与对应测试；增加服务商配置，凭证切换时清空，不持久化。
4. 集成：`cloud_asr.rs`、`asr.rs`、`asr_jobs.rs` 和新 AssemblyAI 适配器；向后兼容老配置、统一时间偏移/异常/取消，补齐回归测试。
5. 构建、审查和交付：完整测试、安装包、原项目基线冲突检查、逐文件散列验证及 1.9.0 备份。

## 公共契约

- `CloudAsrConfig` 增加 `provider`, `app_id`, `secret_id`, `secret_key`；没有 provider 的老请求视为 `compatible`。`api_key` 和其他凭证仅会话内使用、跳过序列化。
- 原有 `base_url`, `model`, `api_key` 保留；官方预设只使用官方域名，Azure 使用资源根地址；测试环境仅允许本机回环地址。
- 三个新适配模块均提供 `transcribe(ctx, wav, config, language, cancelled) -> Result<Vec<Cue>>`；输入为有界 16 kHz 单声道 WAV，返回相对片段的真实时间戳，由集成层加上偏移。
- `cloud:<model>` 旧任务标识继续恢复；新标识记录服务商、模型，不记录密钥或地址。只有已明确支持的兼容服务提供额外翻译。
- HTTPS、证书校验、禁止自动重定向；认证错误、余额不足、超时与无时间戳均不误报成功，且多字段凭证均脱敏。

## 回归重点

- 凭证出现在 URL、错误或服务回显中不能泄露；切换服务商必须清除旧密钥。
- 短音频正常、无时间戳/静音拒绝伪字幕；跨多个分块的时间戳加正确偏移。
- 默认选择、异步配置、旧记录重试以及已有本地模型保持兼容。
- 未完成上传、轮询超时、取消和删除均不得写出完成状态。
- 每家官方请求和解析用本机模拟服务检验；真实服务单列验收，不以模拟结果冒充实测。
